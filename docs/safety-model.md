# 安全模型

文件名、路径、大小和时间都不足以判断内容相同；它们只用于减少读取。快速指纹同样不能成为删除结论，因为不同文件仍可能碰撞或只在未采样区域不同。

离线卷是未知状态，不是不存在。因此离线只能展示为 `offline`，不能批量产生 `missing` 或 `deleted`。重复内容也不必然冗余：同一物理硬盘两个分区、不同恢复时间点和异地副本有不同价值。

清理计划只接受完整哈希内容组，并要求指定保留卷有在线 `present` 副本、移除候选后在线独立存储对象数满足阈值。其输出即使为 `candidate_unverified` 也只是人工审核材料。本阶段没有永久删除、移动、废纸篓或隔离区执行代码路径。

索引中的完整哈希只在文件大小、修改时间纳秒、inode 和设备号均与当前文件一致时可被 `lookup` 复用。任一项变化会返回 `cache_stale`，不会产生精确命中，必须重新计算完整哈希。重复报告只把在线 `present` 文件视为当前可信副本；离线卷的最后一次 `present` 记录标为 `offline_unverified`，异常状态不会成为冗余候选。

硬链接是同一存储对象的多个路径，不是多份备份。报告和清理计划按 `storage_object_key` 计算独立对象，并同时显示逻辑卷和物理设备数量。默认计划为 `candidate_unverified`；启用元数据或完整哈希验证并全部通过后才为 `verified_candidate`。任何验证失败、硬链接路径或保留数量不足都应为 `blocked`。

本机 UI 也遵守同一模型：服务固定绑定到 `127.0.0.1`，无遥测、云端传输或外网监听。文件名和路径本身敏感，用户不应将 UI 端口转发到局域网或公网。
